# OMR Exam Grader (Web)

โปรแกรมตรวจข้อสอบจากกระดาษคำตอบที่ฝนด้วยดินสอ 2B (OMR) ทำงานในเบราว์เซอร์ล้วน ไม่ต้องติดตั้ง ไม่อัปโหลดไฟล์ไปไหน

## ทำอะไรได้บ้าง (สรุปสั้น)

- อัปโหลด **PDF สแกนเฉลย 1 ใบ** + **PDF สแกนกระดาษคำตอบหลายหน้า** (1 หน้า = 1 คน) แล้วได้ **ตารางผลบนหน้าเว็บ + ไฟล์ CSV**
- **ไม่ต้องตั้งค่าฟอร์ม ไม่ต้องลากกรอบ** — เฉลยเป็นตัว "สอน" โปรแกรมเองว่าฟอร์มมีกี่บล็อก กี่ข้อ กี่ตัวเลือก
- แยกประเภทบล็อกอัตโนมัติ: บล็อกคำตอบ / บล็อกข้อมูลผู้สอบ (รหัสนักศึกษา, รหัสวิชา) / ช่องที่เฉลยไม่ฝน (เช่น เพศ → ส่งออกค่าดิบ)
- ถอดรหัสนักศึกษา รหัสวิชา และข้อมูลอื่นออกเป็นคอลัมน์ใน CSV
- ให้คะแนนเทียบเฉลย โดยคะแนนเต็ม = จำนวนข้อที่เฉลยฝน
- ตรวจจับใบที่ต้องตรวจซ้ำ (ฝนไม่ครบ, ฝนหลายช่อง, จัดภาพไม่แน่ใจ) พร้อมเหตุผล
- คลิกแถวเพื่อดูภาพกระดาษที่วงทับช่องที่อ่านได้ (เขียว = ถูก, แดง = ผิด, น้ำเงิน = คำตอบที่ถูก)
- ปรับสัญลักษณ์ตัวเลือกได้ (1-5 / ก-จ / A-E) และตั้งชื่อหัวคอลัมน์ของบล็อกข้อมูลเองได้
- CSV เป็น UTF-8 with BOM เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน มีตัวเลือกกัน Excel ตัดเลข 0 นำหน้า
- ใช้ได้กับ Safari / Chrome บน Mac; รับไฟล์ภาพ (PNG/JPG) ได้ด้วย (1 ภาพ = 1 หน้า)

## วิธีใช้

1. เปิด `index.html` ในเบราว์เซอร์
2. **ขั้นที่ 1** เลือก PDF เฉลย → ดูภาพที่วงทับ, สรุปบล็อก, ตารางข้อ → คำตอบ, คะแนนเต็ม → เทียบกับกระดาษจริง แล้วกด **ยืนยันเฉลย**
3. **ขั้นที่ 2** เลือก PDF กระดาษคำตอบ → รอตรวจ → ดูตาราง / คลิกแถวดูภาพ → **ดาวน์โหลด CSV**

ข้อกำหนดของไฟล์สแกน: สี หรือ grayscale ที่ ≥ 200 dpi (ไม่ใช่ขาวดำล้วน เพราะวงกลมเขียวอ่อนอาจหาย) และเป็นฟอร์มชุดเดียวกันทั้งไฟล์

ออนไลน์/ออฟไลน์: PDF.js โหลดจากอินเทอร์เน็ต (CDN) ก่อน ถ้าโหลดไม่ได้หรือไม่มีเน็ต (รอสูงสุดประมาณ 6 วินาทีต่อไฟล์) จะใช้ไฟล์ในโฟลเดอร์ `lib/` (`pdf.min.js`, `pdf.worker.min.js` v3.11.174 ซึ่งแนบมากับโปรเจกต์แล้ว) แทนโดยอัตโนมัติ จึงใช้ได้ทั้งบนเว็บและเปิดไฟล์ในเครื่องโดยไม่ต่อเน็ต — ต้องเก็บโฟลเดอร์ `lib/` ไว้ข้างไฟล์ `index.html` เสมอ

## การเตรียมเฉลย (สำคัญที่สุด)

เฉลยคือสิ่งที่ "สอน" โปรแกรม — คะแนนเต็ม โครงสร้างฟอร์ม และชนิดของแต่ละบล็อกมาจากเฉลยทั้งหมด ถ้าเฉลยผิด ทุกใบจะผิดตาม ควรเตรียมให้ดีก่อนตรวจจริง

### ก. ทำกระดาษเฉลย
ใช้กระดาษคำตอบ **ฟอร์มเดียวกับที่นักศึกษาใช้** (ชุด/รุ่นเดียวกัน) แล้วฝนดังนี้

| บล็อก | ต้องฝนอย่างไร | โปรแกรมจะเข้าใจว่า |
|---|---|---|
| ข้อมูลผู้สอบ (เลขประจำตัว, รหัสวิชา ฯลฯ) | ฝน **แถว 0 ครบทุกคอลัมน์** (ไม่ขาดคอลัมน์ใด) | บล็อกข้อมูล — ไม่ตรวจ แต่ถอดค่าลง CSV |
| ข้อสอบ | ฝน **1 ช่องต่อ 1 ข้อ** เฉพาะข้อที่มีจริง | บล็อกคำตอบ — ตรวจเทียบเฉลย |
| ข้อสอบส่วนที่เกิน (เช่น ข้อสอบมี 80 ข้อ ฟอร์มมี 100 ข้อ) | **ไม่ฝน** | ไม่นำมาคิดคะแนน |
| ช่องอื่นที่ต้องการเก็บค่า (เช่น เพศ) | **ไม่ฝนเลย** | ช่องดิบ — ส่งออกค่าที่นักศึกษาฝนเป็นคอลัมน์ใน CSV |

ข้อควรระวัง
- ฝนให้ **เข้มและเต็มวง** เหมือนที่นักศึกษาควรฝน (ดินสอ 2B) ห้ามฝนจาง
- **ห้ามมีรอยลบหรือรอยเปื้อน** ในเฉลย และห้ามฝนข้อเดียวหลายช่อง (ข้อนั้นจะถูกข้ามและมีคำเตือน)
- ถ้าข้อสอบมี 80 ข้อ ต้องฝนครบ 80 ข้อ ข้อไหนลืมฝน ข้อนั้นจะไม่ถูกนับเข้าคะแนนเต็ม
- ถ้ามีบล็อกเลือกอื่นที่ไม่ใช่ข้อมูลผู้สอบ (เช่น เลขที่แบบทดสอบ) และไม่อยากให้ถูกอ่านเป็นข้อมูล ให้ไม่ฝนในเฉลย

### ข. สแกนเฉลย
- สแกนเป็น **สีหรือ grayscale** ที่ **≥ 200 dpi** (ไม่ใช้ขาวดำล้วน เพราะวงกลมสีเขียวอ่อนอาจหาย)
- วางกระดาษตรง ภาพครบทั้งแผ่น ไม่ตัดขอบที่มีวงกลม ไม่มีเงาหรือรอยพับพาดผ่านวงกลม
- ใช้ **เครื่องสแกน/ตั้งค่าเดียวกัน** กับที่จะสแกนกระดาษคำตอบ เพื่อให้ขนาดภาพเท่ากัน
- ไฟล์เฉลยมี 1 หน้า (ถ้ามีหลายหน้า โปรแกรมใช้เฉพาะหน้าแรก)

### ค. ตรวจความถูกต้องของเฉลยก่อนยืนยัน (ขั้นที่ 1)
โปรแกรมจะแสดงผลที่อ่านได้ให้ตรวจ ก่อนกด **ยืนยันเฉลย** ให้ไล่เช็คตามรายการนี้ (ถ้าไม่ยืนยัน จะเข้าขั้นที่ 2 ไม่ได้)

- [ ] **จำนวนวงกลมและบล็อกถูกต้อง** — ข้อความสรุปบอกจำนวนวงกลม บล็อกคำตอบ/ข้อมูล/ช่องดิบ ให้ตรงกับฟอร์มจริง (ฟอร์มตัวอย่าง: วงกลม ≈ 632, บล็อกคำตอบ 5, ข้อมูลผู้สอบ 2, ช่องดิบ 1 [เพศ])
- [ ] **ภาพที่วงทับ** — ทุกวงกลมต้องมีวงสีทับ ไม่มีช่องที่ขาด (วงแดง = ไม่พบวงกลมจริง ใช้ตำแหน่งตามกริดแทน) ช่องที่ฝนต้องเป็นสีเขียว ช่องที่ไม่ได้ฝนต้องเป็นสีเทา ซูมที่ 160%/240% เพื่อดูรายละเอียด
- [ ] **กรอบสีของบล็อก** — น้ำเงิน = คำตอบ, ม่วง = ข้อมูลผู้สอบ, ส้ม = ช่องดิบ ตรวจว่าแต่ละกรอบครอบถูกบล็อก และไม่มีบล็อกที่ถูกตัดแบ่งหรือรวมกัน
- [ ] **คะแนนเต็ม** — "คะแนนเต็ม = N ข้อ" ต้องเท่ากับจำนวนข้อสอบจริง
- [ ] **ตารางเฉลย** — เปรียบเทียบกับกระดาษเฉลยทุกข้อ (ข้อที่ไม่มีเฉลยขึ้น `–`) ข้อที่ขึ้น `–` โดยไม่ควรเป็นต้องกลับไปดูว่าฝนจาง/ฝนซ้ำ
- [ ] **บล็อกข้อมูลผู้สอบ** — ต้องมีเลขหลักครบ (เช่น 10 หลัก, 3 หลัก) และไม่มีคำเตือน "เฉลยไม่ได้ฝนคอลัมน์ที่ …" ถ้ามี แปลว่าแถว 0 ขาดคอลัมน์
- [ ] **ชื่อบล็อก** — ตั้งชื่อบล็อกข้อมูลให้สื่อความหมาย (เช่น รหัสนักศึกษา, รหัสวิชา) เพราะเป็นหัวคอลัมน์ใน CSV
- [ ] **คำเตือนสีเหลือง** — อ่านทุกข้อ:

| คำเตือน | ความหมาย | วิธีแก้ |
|---|---|---|
| ข้อที่เฉลยไม่ฝน (ไม่นำมาคิดคะแนน): … | ข้อเหล่านี้ไม่มีคำตอบในเฉลย | ถ้าเป็นข้อเกินจริงที่ตั้งใจให้ว่าง ปล่อยไว้ได้ ถ้าไม่ใช่ ให้ฝนเฉลยเพิ่มแล้วสแกนใหม่ |
| เฉลยข้อ N ฝนหลายช่อง | ฝนซ้ำหรือมีรอยลบ | ทำเฉลยใหม่ให้สะอาด |
| บางช่องหาวงกลมไม่เจอ | วงกลมจางหรือติดเส้น | เปิด "ดูภาพ debug" แล้วปรับ "ความไวต่อขอบวงกลม" |
| ไม่พบเฉลยที่ฝนเลย | เกณฑ์เข้มเกินไปหรือฝนจาง | ลดเกณฑ์ความเข้ม หรือฝนเฉลยใหม่ให้เข้มขึ้น |

- [ ] **ภาพ debug** — ติ๊ก "ดูภาพ debug" จะเห็นสิ่งที่โปรแกรมมองเห็นเป็นเส้น (ดำบนขาว) วงกลมต้องเป็นวงปิดและแยกจากกัน ถ้าวงติดกันหรือติดเส้นตาราง ให้ลด "ความไวต่อขอบวงกลม" ถ้าวงขาด/จาง ให้เพิ่ม
- [ ] เมื่อปรับ "ตั้งค่าขั้นสูง" ใด ๆ ให้กด **วิเคราะห์เฉลยใหม่** แล้วตรวจรายการข้างบนซ้ำ — ต้องยืนยันเฉลยใหม่ทุกครั้งที่วิเคราะห์ใหม่

### ง. ทดสอบก่อนตรวจจริง (แนะนำ)
1. ยืนยันเฉลยแล้ว ลองอัปโหลดกระดาษคำตอบ **2–3 ใบ** ที่รู้คำตอบอยู่แล้ว (เช่น ใบที่ฝนตามเฉลยเป๊ะ ใบที่ตั้งใจฝนผิดบางข้อ ใบที่เว้นว่างบางข้อ)
2. เช็คว่า **คะแนนตรงกับที่คาดไว้**, รหัสนักศึกษาอ่านได้ครบ, ใบที่เว้นว่าง/ฝนซ้อนถูก flag ว่า "ต้องตรวจซ้ำ" ตรงข้อ
3. คลิกแถวดูภาพ: วงต้องทับตรงช่อง ไม่เหลื่อม (ถ้าเหลื่อม แปลว่าจัดภาพมีปัญหา)
4. ถ้าทุกอย่างถูก ค่อยอัปโหลดทั้งชุด; หลังตรวจเสร็จ เปิด "แสดงเฉพาะใบที่ต้องตรวจซ้ำ" แล้วดูภาพทีละใบ และสุ่มเช็คใบที่ "ปกติ" อีกส่วนหนึ่ง
5. ตรวจเทียบกับผลที่ตรวจด้วยตา 5–10 ใบในครั้งแรกที่ใช้ฟอร์มใหม่ แล้วปรับ "เกณฑ์ความเข้มของการฝน" ถ้าจำเป็น

## โครงสร้างโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | แอปทั้งหมด (HTML + CSS + JS ไฟล์เดียว) |
| `lib/` | PDF.js v3.11.174 สำรองสำหรับใช้ออฟไลน์ (ใช้เมื่อโหลดจาก CDN ไม่ได้) |

## หลักการทำงาน

ไลบรารี: **PDF.js** แปลงหน้า PDF เป็นภาพ (200 dpi ค่าเริ่มต้น) และ **Canvas API** อ่านพิกเซล ไม่ได้ใช้ OpenCV.js (อัลกอริทึมเขียนเองใน JS)

### 1) หาวงกลม (`prepare` → `detect`)
- อ่านภาพเป็น 2 ช่องสัญญาณ: **minCh** (ค่าต่ำสุดของ R,G,B — หมึกสีเขียวเห็นเข้ม ใช้หาวงกลม) และ **maxCh** (ค่าสูงสุด — หมึกสีเขียวหายไป เหลือแต่ดินสอสีเทา ใช้วัดการฝน)
- ทำ binary ที่ระดับ `paper × ความไว` → ขยาย 1 px → connected components → กรองด้วยขนาด สัดส่วน และอัตราเติม (ตัดสี่เหลี่ยมทึบของ timing mark ออก)
- หาขนาดวงกลมที่พบบ่อยที่สุด (D) แล้วเก็บเฉพาะวงที่ขนาดใกล้เคียง
- ตรวจมุมเอียงจากแนววงกลมที่อยู่ติดกัน แล้วหมุนภาพแก้ก่อน (`estimateAngle`, `rotateCanvas`)

### 2) จัดกลุ่มเป็นบล็อก (`buildBlocks`)
- เชื่อมวงกลมที่อยู่ติดกันตามแนวแถว/คอลัมน์ (ระยะ ≤ 1.6 เท่าของระยะห่างปกติ) → แต่ละกลุ่ม = 1 บล็อก
- ในบล็อก จัดกลุ่มพิกัด x/y เป็นคอลัมน์/แถว และเติมแถว/คอลัมน์ที่วงกลมหายไปตรงกลางตามระยะห่างปกติ

### 3) ให้เฉลยสอนโปรแกรม (`analyzeKey`)
วัดความเข้มทุกช่อง ลบด้วยค่ากลางของทั้งหน้า (ช่องว่าง) ช่องที่เกินเกณฑ์ (ค่าเริ่มต้น 15%) = ฝน แล้วแยกประเภทบล็อก:

| รูปแบบการฝนในเฉลย | ประเภท | การใช้งาน |
|---|---|---|
| ฝนแถวเดียวกันหลายคอลัมน์ (≥ 50% ของคอลัมน์) และไม่มีฝนที่อื่น | ข้อมูลผู้สอบ | ไม่ตรวจ ถอดค่า: ตำแหน่งแถวที่ฝนในแต่ละคอลัมน์ = ตัวเลข |
| ฝนอย่างอื่น | คำตอบ | แถวที่ฝน 1 ช่อง = ข้อที่ตรวจ |
| ไม่ฝนเลย แต่ขนาดเท่าบล็อกคำตอบ | คำตอบ (ข้อเกินเฉลย) | นับเลขข้อต่อ แต่ไม่คิดคะแนน |
| ไม่ฝนเลย ขนาดอื่น | ช่องดิบ (เช่น เพศ) | ส่งออกค่าที่นักศึกษาฝนใน CSV |

- ข้อเรียงเลขต่อกันจากบล็อกซ้าย → ขวา
- **คะแนนเต็ม = จำนวนข้อที่เฉลยฝน 1 ช่อง**

### 4) จัดภาพกระดาษแต่ละใบให้ทับเฉลย (`alignPoints`)
- เทียบตำแหน่งวงกลมของใบนักศึกษากับของเฉลย: โหวตหาการเลื่อน (translation) แล้วปรับละเอียดด้วย ICP + affine (รองรับเลื่อน เอียง ยืดเล็กน้อย)
- ถ้าจับคู่วงกลมได้ < 60% จะ flag "จัดภาพไม่แน่ใจ"
- วัดการฝนที่ตำแหน่งของเฉลยที่แปลงแล้ว (snap เข้าหาวงกลมที่พบถ้าห่าง < 0.4 D) จึงอ่านได้แม้หาวงกลมของใบนั้นไม่เจอบางช่อง

### 5) ตัดสินการฝน (`pick`) และให้คะแนน (`gradeStudent`)
- ช่องที่เกินเกณฑ์ = ฝน; ช่องที่จางกว่า 55% ของช่องที่เข้มสุดในข้อเดียวกันถือเป็นรอยลบ ไม่นับ
- ข้อคำตอบ: ฝน 1 ช่อง → เทียบเฉลย / ไม่ฝน → ผิด + "ฝนไม่ครบ" / ฝนหลายช่อง → ผิด + "ฝนหลายช่อง"
- บล็อกข้อมูล: คอลัมน์ที่ไม่ฝนขึ้น `?`, ฝนหลายช่องขึ้น `*` พร้อม flag
- สถานะ "ปกติ" หรือ "ต้องตรวจซ้ำ: เหตุผล…"

## ความเสี่ยง / ข้อควรระวัง
- ขั้นหาวงกลมอัตโนมัติคือความเสี่ยงหลัก (ฟอร์มสีเขียว เส้นจาง) — มี **ภาพ debug** และตัวปรับ "ความไวต่อขอบวงกลม" ใน "ตั้งค่าขั้นสูง"
- เฉลยต้องฝนแถว 0 ให้ครบทุกคอลัมน์ของบล็อกข้อมูล ถ้าขาดคอลัมน์ ขั้นที่ 1 จะแจ้งเตือน
- ออฟไลน์ใช้ได้ผ่าน `lib/` แต่การเปิดแบบ file:// จะรัน PDF.js ในหน้าหลัก (fake worker) ซึ่งช้ากว่าเล็กน้อย; ถ้าช้าให้เปิดผ่านเซิร์ฟเวอร์ local เช่น `python3 -m http.server`

# OMR Exam Grader (Web)

โปรแกรมตรวจข้อสอบจากกระดาษคำตอบที่ฝนด้วยดินสอ 2B (OMR) ทำงานในเบราว์เซอร์ล้วน ไม่ต้องติดตั้ง ไม่อัปโหลดไฟล์ไปไหน

## ทำอะไรได้บ้าง (สรุปสั้น)

- อัปโหลด **PDF สแกนเฉลย 1 ใบ** + **PDF สแกนกระดาษคำตอบหลายหน้า** (1 หน้า = 1 คน) แล้วได้ **ตารางผลบนหน้าเว็บ + ไฟล์ CSV**
- **ไม่ต้องตั้งค่าฟอร์ม ไม่ต้องลากกรอบ** — เฉลยเป็นตัว "สอน" โปรแกรมเองว่าฟอร์มมีกี่บล็อก กี่ข้อ กี่ตัวเลือก
- แยกประเภทบล็อกอัตโนมัติ: บล็อกคำตอบ / บล็อกข้อมูลผู้สอบ (รหัสนักศึกษา, รหัสวิชา) / ช่องที่เฉลยไม่ฝน (เช่น เพศ → ส่งออกค่าดิบ)
- ถอดรหัสนักศึกษา รหัสวิชา และข้อมูลอื่นออกเป็นคอลัมน์ใน CSV
- ให้คะแนนเทียบเฉลย โดยคะแนนเต็ม = จำนวนข้อที่เฉลยฝน
- ตรวจจับใบที่ต้องตรวจซ้ำ (ฝนไม่ครบ, ฝนหลายช่อง, จัดภาพไม่แน่ใจ) พร้อมเหตุผล
- คลิกแถวเพื่อดูภาพกระดาษที่วงทับช่องที่อ่านได้ (เขียว = ถูก, แดง = ผิด, น้ำเงิน = คำตอบที่ถูก)
- ปรับสัญลักษณ์ตัวเลือกได้ (1-5 / ก-จ / A-E) และตั้งชื่อหัวคอลัมน์ของบล็อกข้อมูลเองได้
- CSV เป็น UTF-8 with BOM เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน มีตัวเลือกกัน Excel ตัดเลข 0 นำหน้า
- ใช้ได้กับ Safari / Chrome บน Mac; รับไฟล์ภาพ (PNG/JPG) ได้ด้วย (1 ภาพ = 1 หน้า)

## วิธีใช้

1. เปิด `index.html` ในเบราว์เซอร์
2. **ขั้นที่ 1** เลือก PDF เฉลย → ดูภาพที่วงทับ, สรุปบล็อก, ตารางข้อ → คำตอบ, คะแนนเต็ม → เทียบกับกระดาษจริง แล้วกด **ยืนยันเฉลย**
3. **ขั้นที่ 2** เลือก PDF กระดาษคำตอบ → รอตรวจ → ดูตาราง / คลิกแถวดูภาพ → **ดาวน์โหลด CSV**

ข้อกำหนดของไฟล์สแกน: สี หรือ grayscale ที่ ≥ 200 dpi (ไม่ใช่ขาวดำล้วน เพราะวงกลมเขียวอ่อนอาจหาย) และเป็นฟอร์มชุดเดียวกันทั้งไฟล์

ใช้ออฟไลน์: PDF.js โหลดจาก CDN ตามค่าเริ่มต้น ถ้าไม่มีอินเทอร์เน็ต ให้วาง `pdf.min.js` และ `pdf.worker.min.js` (v3.11.174) ไว้ในโฟลเดอร์ `lib/` ข้างไฟล์ HTML โปรแกรมจะใช้ไฟล์ในโฟลเดอร์ก่อน

## โครงสร้างโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | แอปทั้งหมด (HTML + CSS + JS ไฟล์เดียว) |
| `test/harness.js` | ตัวสร้างฟอร์มจำลองด้วย canvas ไว้ทดสอบระหว่างพัฒนา (ไม่ใช้ตอนใช้งานจริง) |
| `lib/` (ไม่บังคับ) | PDF.js สำหรับใช้ออฟไลน์ |

## หลักการทำงาน

ไลบรารี: **PDF.js** แปลงหน้า PDF เป็นภาพ (200 dpi ค่าเริ่มต้น) และ **Canvas API** อ่านพิกเซล ไม่ได้ใช้ OpenCV.js (อัลกอริทึมเขียนเองใน JS)

### 1) หาวงกลม (`prepare` → `detect`)
- อ่านภาพเป็น 2 ช่องสัญญาณ: **minCh** (ค่าต่ำสุดของ R,G,B — หมึกสีเขียวเห็นเข้ม ใช้หาวงกลม) และ **maxCh** (ค่าสูงสุด — หมึกสีเขียวหายไป เหลือแต่ดินสอสีเทา ใช้วัดการฝน)
- ทำ binary ที่ระดับ `paper × ความไว` → ขยาย 1 px → connected components → กรองด้วยขนาด สัดส่วน และอัตราเติม (ตัดสี่เหลี่ยมทึบของ timing mark ออก)
- หาขนาดวงกลมที่พบบ่อยที่สุด (D) แล้วเก็บเฉพาะวงที่ขนาดใกล้เคียง
- ตรวจมุมเอียงจากแนววงกลมที่อยู่ติดกัน แล้วหมุนภาพแก้ก่อน (`estimateAngle`, `rotateCanvas`)

### 2) จัดกลุ่มเป็นบล็อก (`buildBlocks`)
- เชื่อมวงกลมที่อยู่ติดกันตามแนวแถว/คอลัมน์ (ระยะ ≤ 1.6 เท่าของระยะห่างปกติ) → แต่ละกลุ่ม = 1 บล็อก
- ในบล็อก จัดกลุ่มพิกัด x/y เป็นคอลัมน์/แถว และเติมแถว/คอลัมน์ที่วงกลมหายไปตรงกลางตามระยะห่างปกติ

### 3) ให้เฉลยสอนโปรแกรม (`analyzeKey`)
วัดความเข้มทุกช่อง ลบด้วยค่ากลางของทั้งหน้า (ช่องว่าง) ช่องที่เกินเกณฑ์ (ค่าเริ่มต้น 15%) = ฝน แล้วแยกประเภทบล็อก:

| รูปแบบการฝนในเฉลย | ประเภท | การใช้งาน |
|---|---|---|
| ฝนแถวเดียวกันหลายคอลัมน์ (≥ 50% ของคอลัมน์) และไม่มีฝนที่อื่น | ข้อมูลผู้สอบ | ไม่ตรวจ ถอดค่า: ตำแหน่งแถวที่ฝนในแต่ละคอลัมน์ = ตัวเลข |
| ฝนอย่างอื่น | คำตอบ | แถวที่ฝน 1 ช่อง = ข้อที่ตรวจ |
| ไม่ฝนเลย แต่ขนาดเท่าบล็อกคำตอบ | คำตอบ (ข้อเกินเฉลย) | นับเลขข้อต่อ แต่ไม่คิดคะแนน |
| ไม่ฝนเลย ขนาดอื่น | ช่องดิบ (เช่น เพศ) | ส่งออกค่าที่นักศึกษาฝนใน CSV |

- ข้อเรียงเลขต่อกันจากบล็อกซ้าย → ขวา
- **คะแนนเต็ม = จำนวนข้อที่เฉลยฝน 1 ช่อง**

### 4) จัดภาพกระดาษแต่ละใบให้ทับเฉลย (`alignPoints`)
- เทียบตำแหน่งวงกลมของใบนักศึกษากับของเฉลย: โหวตหาการเลื่อน (translation) แล้วปรับละเอียดด้วย ICP + affine (รองรับเลื่อน เอียง ยืดเล็กน้อย)
- ถ้าจับคู่วงกลมได้ < 60% จะ flag "จัดภาพไม่แน่ใจ"
- วัดการฝนที่ตำแหน่งของเฉลยที่แปลงแล้ว (snap เข้าหาวงกลมที่พบถ้าห่าง < 0.4 D) จึงอ่านได้แม้หาวงกลมของใบนั้นไม่เจอบางช่อง

### 5) ตัดสินการฝน (`pick`) และให้คะแนน (`gradeStudent`)
- ช่องที่เกินเกณฑ์ = ฝน; ช่องที่จางกว่า 55% ของช่องที่เข้มสุดในข้อเดียวกันถือเป็นรอยลบ ไม่นับ
- ข้อคำตอบ: ฝน 1 ช่อง → เทียบเฉลย / ไม่ฝน → ผิด + "ฝนไม่ครบ" / ฝนหลายช่อง → ผิด + "ฝนหลายช่อง"
- บล็อกข้อมูล: คอลัมน์ที่ไม่ฝนขึ้น `?`, ฝนหลายช่องขึ้น `*` พร้อม flag
- สถานะ "ปกติ" หรือ "ต้องตรวจซ้ำ: เหตุผล…"

### คอลัมน์ CSV
`ลำดับหน้า` · บล็อกข้อมูลผู้สอบ · ช่องดิบ · `คะแนนรวม` · `คะแนนเต็ม` · `สถานะ` · `ข้อ 1 … ข้อ N` (เลือกได้ว่าเป็นคำตอบที่ฝน หรือ 1/0 ถูก-ผิด; `-` = ไม่ฝน, `*` = หลายช่อง)

### ยังไม่ได้ทำ / ยังไม่ได้ยืนยัน

- [ ] ยืนยันว่าช่อง "เลขที่แบบทดสอบ/ชุดวิชา" ฝนหรือเขียนมือ (ถ้าฝน ระบบอ่านเป็นบล็อกข้อมูลอยู่แล้ว)
- [ ] ยังไม่ได้อ่านค่าจาก timing marks โดยตรง (จัดภาพด้วยตำแหน่งวงกลมแทน)

- [ ] ยังไม่มีไฟล์ PDF.js ใน `lib/` (ใช้ CDN)

## ความเสี่ยง / ข้อควรระวัง
- ขั้นหาวงกลมอัตโนมัติคือความเสี่ยงหลัก (ฟอร์มสีเขียว เส้นจาง) — มี **ภาพ debug** และตัวปรับ "ความไวต่อขอบวงกลม" ใน "ตั้งค่าขั้นสูง"
- เฉลยต้องฝนแถว 0 ให้ครบทุกคอลัมน์ของบล็อกข้อมูล ถ้าขาดคอลัมน์ ขั้นที่ 1 จะแจ้งเตือน
- ใช้ CDN ต้องมีอินเทอร์เน็ต (หรือวางไฟล์ใน `lib/`)

## ทดสอบระหว่างพัฒนา
เปิดหน้าผ่านเซิร์ฟเวอร์ local (เช่น `python3 -m http.server 8765` ในโฟลเดอร์โปรเจกต์) แล้วในคอนโซลเบราว์เซอร์โหลด `test/harness.js` ซึ่งจะสร้างฟอร์มจำลองในตัวแปร `T` และแทนที่ `openSource`:

```js
// หลังโหลด test/harness.js
S.keyFile = 'KEY'; await runKey(); setConfirmed(true);
S.stuSrc = await openSource('STU'); S.results = [];
for (let p = 1; p <= 4; p++) S.results.push(gradeStudent(analyze(await S.stuSrc.render(p), false), p));
// เทียบ S.results[i].score กับ T.stu[i].expect และรหัสกับ T.stu[i].id
```
